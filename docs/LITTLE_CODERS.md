# Little Coders (ages 6–11)

Little Coders is five **independent courses** of eight lessons each. Every course ends with its
own assessment and the program closes with one final assessment:

| # | Course | Tool | Lessons | Assessment |
|---|---|---|---|---|
| 1 | Scratch Adventures | MIT Scratch | 8 | Course Assessment |
| 2 | Scratch Game Studio | MIT Scratch | 8 | Course Assessment |
| 3 | AI for Kids: Smart Projects | Generation AI Teachable Machine + Stretch3 (TM2Scratch) | 8 | Course Assessment |
| 4 | Python Explorers *(was "Python for Young Builders")* | EduBlocks | 8 | Course Assessment |
| 5 | Python Creative Lab | EduBlocks | 8 | Course Assessment |
| – | Little Coders | – | – | Final Assessment |

40 lessons + 5 course assessments + 1 final assessment = **46 classes** (about six months at
two classes a week). Families enrol **one course at a time**; the order above is the
recommended progression, not a compulsory package. Lesson `k` of course `n` is class
`Lesson.order = 9(n-1)+k`; that course's assessment is class `9n`; the Final Assessment is class `46`.

Nothing here changes any other program. Lumexa Odyssey and Advanced Data Science keep
reusing the older `little-coders-path.json` modules (including "Python for Young Builders")
exactly as before.

## Migration (safe, additive, idempotent)

The SQL migration `20261112000000_little_coders_v2` only **adds** tables, columns and enum
values. The data migration runs on boot (after the course seed) and:

- keeps every existing `Lesson` row and id, so progress, class records, homework submissions,
  scheduled lessons, certificates, payments and credits stay attached. The old content of each
  lesson is kept as a snapshot in `sourceRefs.legacyLittleCodersV1`;
- works **by position**: a row keeps its id and its class number and takes the authored content
  of that position. Scratch Adventures (1–9) and AI for Kids (19–27) keep their module rows; the
  old *Python for Young Builders* module (10–17) is renamed **Scratch Game Studio** (10–18);
  **Python Explorers** (28–36) and **Python Creative Lab** (37–45) are new;
- moves the old **Final Test** row from position 28 to position 46 (with the class records
  that point at it) so a student who already graduated stays graduated;
- detaches custom-course assessments that were linked to the retired banks;
- never overwrites what an administrator edited (`sourceRefs.lcV2.edited[]`), and does nothing
  on the second run (`LC_SPEC_VERSION` / `LC_BANK_VERSION`).

Positional scheduling (`ScheduledLesson.lessonNumber == Lesson.order`, next = highest
completed + 1) is unchanged: a student who had finished 12 classes continues with class 13 of
the new structure, and a completed class keeps its record and class number. Upcoming classes
are regenerated by the normal `reconcile`. Students who were part-way through the old Python
module continue in Scratch Game Studio at the same class number.

## Lessons

Every lesson page (shared renderer `LessonStudyView`) shows, top to bottom: the **Your
Learning Preview** video, the mission, concept visuals, interactive demos, real block /
Python examples, common mistakes and tips, the in-class project, the project card and the
homework card with the existing **Submit Homework** workflow. Teacher notes, the video
brief and project instructions are served only to staff (`/curriculum/lessons/:id/teacher-prep`).

- **Preview video.** Metadata (title, duration, storyboard, narration script, poster, captions
  and the video URL) is stored per lesson. The player shows a clear "coming soon" state until
  an administrator pastes a real URL — no video is ever fabricated. Target: 60–100 s (max 120 s),
  1920×1080 MP4, ~100–130 narration words.
- **Project cards.** "Open Project" and "Copy Link" stay disabled while the project URL is
  empty. The "Start Coding" buttons open the platform editor (URLs live in `CodingPlatform`).
- **Demos** are labelled practice simulations. The AI demos use no camera or microphone.

## Assessments

All six use the same standardized layout (**LUMEXA · LITTLE CODERS**, 40 minutes, 40 marks):

| Part | What | Marks |
|---|---|---|
| 01 · Think in Blocks | 10 individually written multiple-choice questions (≥ 4 with a block script) | 10 |
| 02 · Quick Check | 5 true / false | 5 |
| 03 · Build It! | one practical project in Stretch3 (courses 1–3) or EduBlocks (4–5) | 25 |

Review and submission take the last five minutes; there is no negative marking. Objective
parts are auto-graded; answer keys never leave the server until the report is released.
The practical is marked by the teacher against the standard rubric (10 / 6 / 5 / 3 / 1). The
**Final Assessment** is cumulative and carries two practicals (Scratch / AI and Python); the
administrator picks which one a class gets (`PATCH …/scheduled-lessons/:id/variant`).
Course 3's practical can use a prepared model or starter project: set it in the admin
assessment page — it is never invented.

A student can hand in several **files** (`.sb3`, `.py`, screenshots, documents; ≤ 8 files,
15 MB each, 40 MB in total) and up to five **links**. Reports are shared with parents only
after the teacher completes the review.

## Temporary practical files (Cloudflare R2)

Practical files reuse the private homework bucket (`HOMEWORK_R2_BUCKET`, `lumexa-homework`) and
its credentials; nothing new has to be configured. Objects live under their own prefix:

```
assessments/little-coders/<assessmentId>/<studentId>/<attemptId>/<fileId>-<name>
```

| Step | Effect |
|---|---|
| Upload (attempt in progress) | `UPLOADED`; the student may take a file back |
| Submit | files are verified in R2, then `ATTACHED` in the same transaction |
| Teacher opens / downloads | short-lived signed link — **never changes a file's status** |
| Teacher approves the report | files become `DELETE_PENDING` in the **same transaction** that stores the final score, then are removed from R2 |
| R2 error | stays `DELETE_PENDING`; the 10-minute sweep retries (1, 2, 4 … 60 min) |

Only keys under `assessments/` are ever removed. Homework files (`homework/…`), class
recordings and every other object are never touched, and repeating any step is a no-op.
The same service works for any future program that registers a file profile
(`fileProfileFor`).

## What still needs a person

- **Preview videos**: record the 40 videos from the briefs in each lesson's admin panel and paste
  the hosted MP4 URL (plus poster / captions if you have them).
- **Project URLs**: add each lesson's project link (and homework link) in the admin Little
  Coders panel. They are intentionally empty on a fresh install.
- **Course 3 practical**: add the prepared model / starter URL in the admin assessment page.
- **Platform links** (`/admin/coding-platforms`) are seeded with the official editors and can be
  changed or switched off there.
